# 发票二维码识别下载工具（Invoice QR Downloader）

一个 Windows 桌面小工具，用于**批量处理含有二维码的发票 / 票据**：识别二维码、按规则下载对应 PDF、按需转图、按需汇总成 Excel。支持**图片与 PDF 混合输入**（PDF 会先自动转成图片再处理）。无需安装 Python 环境，**双击 `发票二维码工具.exe` 即用**。

最新版本见 [Releases](https://github.com/jianRY/invoice-qr-tool/releases)。

## 它能做什么

1. **PDF 前置转换（自动，无需勾选）**：目标文件夹里只要有 PDF，先自动把 PDF 逐页转成 JPG，再往下走识别 / 下载流程：
   - 全是图片 → 不新建任何文件夹，完全按原逻辑处理；
   - 全是 PDF → 在目标文件夹内新建「处理后」，PDF 转出的图片放入其中，随后处理「处理后」；
   - PDF + 图片混合 → 同样新建「处理后」，PDF 转出的图片 **+ 原有图片的副本** 一起放入，再处理「处理后」（原始图片保留不动）。
   - 转出的页面命名 `原文件名_1.jpg` / `原文件名_2.jpg` …；「处理后」每次处理都重建（其中的 `PDF/` 会在重建前先暂存、建好后原样挪回，**已下载的发票不会丢**）；命名冲突自动加后缀；单个 PDF 损坏 / 加密只跳过该份，不中断整体。
   - 也可单独作为工具运行：`发票二维码工具.exe --pdf2img "<文件夹>"`（只做转换，不识别不下载）。
2. 识别指定文件夹下所有图片中的二维码（基于 `zxing-cpp`，对截图 / 小图自动 1~4 倍放大，识别率高）。**每一张图片都会被识别并归类**，不会因网址重复而整张跳过；去重只发生在下载环节（见下条）。
3. 二维码为**网址** → 自动下载对应 PDF，保存到 `PDF/` 子目录。
   - **一张图只有 1 个二维码** → 文件名与原始图片同名（`原名.pdf`）。
   - **一张图有 2 个及以上二维码** → **每个二维码各自下载一份**，命名为
     `原名_第1页.pdf`、`原名_第2页.pdf` …（编号按二维码在图上**从上到下、从左到右**，
     重跑顺序完全一致，不会张冠李戴）。
   - 内置两种下载策略：直接 PDF 链接；以及需要先进入展示页再解析 `idBase` 的发票平台（如江苏财政电子票据）。
   - **同一张发票只下载一次、只保留一份 PDF**：一张发票上可能带多个二维码（如截图的短链与 PDF 页面上的详情链），内容相同的重复副本会自动合并，最终只留一份；用户自己放进文件夹的源 PDF 一律不动。
   - **重跑同一个文件夹不再重新下载**：已下载且完好的 PDF 直接复用；程序还会把「二维码网址 → 发票内容指纹」记在 `PDF/_去重索引.json`，下次连请求都不发。同一文件夹反复处理，**第 2 轮起的下载次数为 0**；把图片改名后再跑也认得出来。
   - **索引删掉后重跑依然零请求**：`PDF/_去重索引.json` 与 `PDF/_图片指纹.json` 都只在**本次任务期间**有效，任务结束（含中途「停止」）即自动删除。为了让删掉缓存后重跑仍然不白发请求，程序改用**文件系统本身就能推导的关系**兜底：源 PDF 转出的页面图能认出自己来自哪份 PDF；同一批里内容完全相同的图片（同一张发票存了多份）自动结对，只让第一张去请求。
   - **重复票据会留下原图**：如果重新下载回来才发现某张发票与已有 PDF 内容一模一样（说明它还有第二个下载入口，或网址已被平台改动），程序会把这张发票的**原始图片**复制一份到 `未识别/`，加前缀 `重复-`，方便人工核对；原图与已下载的 PDF 均保持不动。同一张发票被拍多张图（二维码网址相同）属**已知去重**，只复用、不重复下载，也不标 `重复-`。
4. 归类与文件处理（**只做“复制”，原图始终留在原文件夹不动**）：
   - 成功识别并下载 PDF → 原图片文件名保持不变；
   - 有问题的图按原因加前缀，一眼看出是什么问题：
     · `无-` —— 图上没有二维码；
     · `非票-` —— 有二维码但下不到 PDF（非网址 / 解析不出可下载内容 / 网络失败）；
     · `重复-` —— 下回来的内容与已有发票完全相同。
   - **一张图有 2 个及以上二维码时，出问题的码会带序号**（按二维码在图上从上到下的位置，
     与 `原名_第N页.pdf` 严格对应），同一原因合并序号、不同原因分开列：
     · 第 2、3 个都下不到 PDF → `未识别/第二、三非票-原名`
     · 第 2 个下不到、第 3 个重复 → `未识别/第二非票、第三重复-原名`

     单二维码不加序号；整图**只复制一份**（**已下成的 PDF 照常保留**，它们是有效票据，不该丢）。
5. 可选开关：**处理完成后自动打开文件夹**。
6. 可选开关：**将下载的 PDF 转为图片**（长边 2000px，短边自适应），保存到 `PDF/图片/`，命名 `原名_第N页.jpg`。
7. 可选开关：**处理完成后汇总发票**（生成 Excel）。针对**江苏省医疗收费票据**模板，提取字段：交款人、票据号码、开票日期、金额合计（小写）、医保统筹基金支付，以及**大病保险支付**、**医疗救助支付**（条件字段，识别到才输出）；输出 `PDF/发票汇总_时间戳.xlsx`，最左侧为**「序号」列**（1、2、3… 配合文件名定位是第几份）；金额类列均为纯数字（无千分位、可直接求和）。「是否重复」列**互指序号**（如「与序号3、5重复」，编号与序号列一致）；右侧分两块汇总 —— **「统计（剔重后）」**（票据张数 / 合计总金额 / 合计总统筹 /〔合计大病保险支付〕/〔合计医疗救助支付〕/ 可赔付金额，全部按剔除重复票据后的口径，同一票号只算第 1 张）与 **「重复票据」**（重复票据张数 / 重复票据金额合计 / 重复票据统筹合计 /〔重复票据大病保险支付合计〕/〔重复票据医疗救助支付合计〕，只统计同票号第 2 张及以后）。可赔付金额 = 合计总金额 − 各支付类合计之和。明细底部「合计」行照旧对全部明细求和（不剔重，「合计」二字写在「文件名」列）。重复判定在程序内部完成，**不依赖 Excel 公式比较票号** —— 票号常超过 15 位，表格软件的 COUNTIF / SUMIF 会按数字截断导致误判（详见更新记录 v4.9.0）。
8. **并发处理（默认 6 路）**：识别 / 下载 / 转图并行推进（下载阶段实测约 5×、识别约 3×）。「汇总发票」保持串行（pdfplumber 纯 Python 解析，并发无收益）。
9. **可随时停止**：处理中可点「停止」，未开始的任务直接取消，已下载的 PDF 与未识别的副本全部保留；再次点「开始处理」会**复用已下载且完好的 PDF，不再重新下载**（图片已转好的也不再重复渲染），直接接着处理剩下的。
10. **单张 PDF 下载自动重试**（最多 2 次、逐次退避），偶发网络抖动不会被误判成「未下载」；「网址确实没有 PDF」属业务性失败，不重试。
11. **处理结束统计**：弹窗 + 日志给出总计图片数、成功下载、**已存在直接复用（未重新下载）**、**同一张发票已下载过（未重复下载）**、识别但未下载、未识别、其它，并附本次耗时与平均每张耗时。
12. **卡片化界面 + 高分屏清晰**：顶栏 + 圆角白卡分区的浅色界面，按钮 / 复选框 / 进度条全部自绘（不跟随系统控件的灰 3D 样式）；日志按级别着色（✓ 绿 / ⚠ 琥珀 / ✗ 红）；进度卡实时显示「正在处理 x / y 份」与「已用 mm:ss」。已开启 **DPI 感知**，125% / 150% / 200% 缩放下文字锐利、不再被整窗位图拉伸。
13. **依托 GitHub 的自动更新**：启动静默检查最新版本，可一键下载并自动替换重启；也可点顶栏右侧「检查更新」手动触发。更新源为公开仓库 Release，**无需任何账号或令牌**。下载过程中可随时点「取消更新」中止（点窗口 ✕ 同样生效），取消后当前版本不变、软件照常可用；仅在「保存新版本」的一两秒内不可取消。

## 使用方法

1. 把待处理的**图片（和/或 PDF）**放进同一个文件夹。
2. 双击 `发票二维码工具.exe`（或运行安装版）。
3. 点「浏览…」选择该文件夹。
4. 按需勾选：
   - 处理完成后打开文件夹
   - 将下载的 PDF 转换为图片（长边 2000px）
   - 处理完成后汇总发票（生成 Excel）
5. 点「▶ 开始处理」，进度卡与日志区实时显示进度；要中止就点右侧的「停止」。
6. 处理完成后（**含 PDF 时，以下均在「处理后」子文件夹内**）：
   - PDF → `PDF/`
   - 转换图片 → `PDF/图片/`
   - 问题图片的副本 → `未识别/`
   - 汇总表 → `PDF/发票汇总_*.xlsx`

顶栏右侧也有「使用说明 / 更新记录」与「检查更新」入口。

## 命名规则速查

> 目标文件夹内**只要出现 PDF**，以下输出全部落在 `处理后/` 内（即 `目标文件夹\处理后\…`）。

| 情况 | 结果 |
| --- | --- |
| 含 PDF（自动前置） | 新建 `处理后/`，PDF 转 `原名_1.jpg`、`原名_2.jpg`… + 复制原有图片进 `处理后/` |
| 网址 + 下载成功（单二维码） | `PDF/<原名>.pdf`，原图片文件名不变 |
| 网址 + 下载成功（≥2 个二维码） | `PDF/<原名>_第1页.pdf`、`<原名>_第2页.pdf`…（每个码各一份） |
| 图上无二维码 | 复制到 `未识别/无-<原名>` |
| 有码但下不到 PDF | 复制到 `未识别/非票-<原名>`（非网址 / 无 PDF / 网络失败） |
| 内容与已有发票相同 | 复制到 `未识别/重复-<原名>` |
| 多二维码有码出问题 | 已成功的 PDF 保留；整图**只复一份**，前缀带序号：<br>`未识别/第二、三非票-<原名>`（第2、3个都非票）<br>`未识别/第二非票、第三重复-<原名>`（第2非票、第3重复） |
| 勾选转图 | `PDF/图片/<原名>_第N页.jpg` |
| 勾选汇总 | `PDF/发票汇总_YYYYMMDD_HHMMSS.xlsx` |

## 技术栈

- Python 3.12 + `tkinter`（GUI）
- `zxing-cpp`（二维码识别）、`OpenCV`（图像预处理）
- `PyMuPDF`（PDF 渲染 / 转图片）、`pdfplumber` + `openpyxl`（发票字段提取与 Excel 汇总）
- `requests`（下载，按线程复用连接池）
- `PyInstaller` 打包为 `--onefile --windowed` 单文件可执行程序

## 从源码构建

需要 Windows 与本机 Python 3.12（含 `tkinter`）：

```bash
python -m venv envs/default
envs/default/Scripts/python.exe -m pip install -r requirements.txt
envs/default/Scripts/python.exe -m PyInstaller 发票二维码工具.spec
# 产物位于 dist/发票二维码工具.exe
```

一键发版（构建双 exe + 自签名 + 同步官网 + 推送 GitHub Release）：

```bash
envs/default/Scripts/python.exe build_release.py --publish
```

## 说明与免责

- 汇总功能目前针对**江苏省医疗收费票据**模板；其它模板可能提取不全（单元格留空或标“解析失败”）。
- PDF 前置转换后的页面能否识别出二维码，取决于原 PDF 中二维码的形式（嵌入图片通常可识别；纯矢量绘制或本就无二维码的 PDF 会判为「未识别」）。
- 本工具仅用于本地批量处理，请妥善保管包含个人票据信息的图片与输出文件。
- EXE 体积较大（约 100MB+，含全部依赖），因此通过 GitHub Releases 分发，而非直接提交进仓库。
